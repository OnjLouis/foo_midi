MIDI Player: Multi-Port Community Build

Version 3.2.3.3. First public preview for foobar2000 2.0 or later on Windows, in either 32-bit or 64-bit form.

This is OnjLouis's community fork of Peter Stuer's foo_midi, itself based on Christopher Snowhill's component. It improves multi-port Yamaha and Roland MIDI playback without changing your MIDI files or synthesizer sounds. It is not an official upstream build.

Installation

  1. Back up your foobar2000 profile and existing foo_midi component with foobar2000 closed.
  2. Download foo_midi.fb2k-component from the community release page. The same package contains both architectures. GitHub's source-code archives are not installable components.
  3. In foobar2000, open File, Preferences, Components, then Install. Select the downloaded component and apply the change. Restart when prompted.
  4. Check that Components lists MIDI Player (Multi-Port Community Build), version 3.2.3.3. Keep only one foo_midi component installed.
  5. Use your existing MIDI player and instrument settings. For a VST instrument, select the VST backend and its instrument in MIDI preferences. No new port switch is required: the component reads the file's routing metadata.

The keyboard-accessible foobar2000 preferences remain the normal configuration interface. This addition introduces no separate custom control panel. External instruments, SoundFonts, ROMs and commercial synthesizer files are not included; obtain any required assets separately with permission.

What changes

  • Standard MIDI Port events and Yamaha sequencer port events route correctly, including changes later in a track.
  • VST playback can use four independent groups of 16 MIDI channels, creating extra instrument instances only when needed.
  • Conservative recognition of complete SC-88 and partial SC-8820 A/B track-name layouts helps files without explicit port events. Explicit routing always takes priority.
  • Recognized Yamaha multi-part and Roland alternate-group SysEx messages reach the intended instance and local part. Global resets and recognized system effects reach declared ports without broadcasting every local part change.
  • Secret Sauce uses the same destination-aware policy while retaining its existing three-port capacity.

Track count is not channel count. Thirty-two tracks may still share sixteen channels; independent channel groups require port metadata or one of the strictly recognized Roland layouts. The build does not guess solely from track count.

Limits

Separate VST instances are not a single hardware module. They do not share its polyphony, global effect processors or cross-port receive-channel reassignment. Recognized parameters are adapted, but proprietary bulk dumps and unknown messages are not translated. Complete hardware parity is not promised.

A destination must be declared by the MIDI file. If absent, the original SysEx is preserved on its source rather than inventing a port. Declared event ports beyond the backend's capacity are not merged into another group. Existing port-number normalization is retained.

Additional instances increase resource use according to the instrument being loaded. Lazy creation avoids starting unused instances, but four expensive instruments can still require substantial CPU and memory. Single-port files should retain their existing routing.

Updates and rollback

Updates to this community fork are manual: download its newest component package, install it through Components and restart. There is no added automatic updater. The upstream component catalogue does not track this fork, and installing an upstream build may replace these changes.

No settings migration is introduced. To roll back, install the previously retained foo_midi component package and restart. Your profile backup is a separate safeguard; do not overwrite settings indiscriminately. Do not load old and new DLLs together.

Testing and feedback

Parser and instrument-bridge regression tests pass in both architectures. They cover independent notes and programs, timing, SysEx, reset cycles, saved state, later port changes, unsupported ports, lazy instance creation and preserved MIDI bytes. Corpus audits and listening checks also covered multi-port Yamaha percussion and Roland demos. Long-running workloads and all instrument combinations have not been exhaustively tested.

Please report reproducible issues with your foobar2000 version and bitness, component version, player backend, instrument version, and the MIDI filename and passage. Comparisons with the upstream component or a permitted hardware recording are useful. Share files only when you have permission; no ROMs or credentials are needed in reports.
