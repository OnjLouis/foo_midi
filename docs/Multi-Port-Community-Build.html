MIDI Player: Multi-Port Community Build

Version 3.2.3.6. Community preview for foobar2000 2.0 or later on Windows, in either 32-bit or 64-bit form.

This is OnjLouis's community fork of Peter Stuer's foo_midi, itself based on Christopher Snowhill's component. It improves multi-port Yamaha and Roland MIDI playback without changing your MIDI files or synthesizer sounds. It is not an official upstream build.

Changelog

3.2.3.6

External MIDI output can send the two parts of a two-port file to different Windows MIDI devices. A single-port file still uses the primary output only.

3.2.3.5

Play MIDI files through a selected Windows MIDI output, including a connected instrument or a virtual port feeding another application. Adds a native port selector, playback-clock scheduling, ordered mid-song SysEx, and note cleanup and state restoration for pause, seek and track changes. Existing software-synth playback remains available.

3.2.3.4

Added optional MU80 / Basic and MU100 / Native voice-map selection for compatible VST instruments.

Installation

  1. Back up your foobar2000 profile and existing foo_midi component with foobar2000 closed.
  2. Download foo_midi.fb2k-component from the community release page. The same package contains both architectures. GitHub's source-code archives are not installable components.
  3. In foobar2000, open File, Preferences, Components, then Install. Select the downloaded component and apply the change. Restart when prompted.
  4. Check that Components lists MIDI Player (Multi-Port Community Build) with the version you installed. Keep only one foo_midi component installed.
  5. Use your existing MIDI player and instrument settings. For a VST instrument, select the VST backend and its instrument in MIDI preferences. No new port switch is required: the component reads the file's routing metadata.

The keyboard-accessible foobar2000 preferences remain the normal configuration interface. External instruments, SoundFonts, ROMs and commercial synthesizer files are not included; obtain any required assets separately with permission.

What changes

  • Standard MIDI Port events and Yamaha sequencer port events route correctly, including changes later in a track.
  • VST playback can use four independent groups of 16 MIDI channels, creating extra instrument instances only when needed.
  • Conservative recognition of complete SC-88 and partial SC-8820 A/B track-name layouts helps files without explicit port events. Explicit routing always takes priority.
  • Recognized Yamaha multi-part and Roland alternate-group SysEx messages reach the intended instance and local part. Global resets and recognized system effects reach declared ports without broadcasting every local part change.
  • Secret Sauce uses the same destination-aware policy while retaining its existing three-port capacity.

Track count is not channel count. Thirty-two tracks may still share sixteen channels; independent channel groups require port metadata or one of the strictly recognized Roland layouts. The build does not guess solely from track count.

MU voice-map selection

Open MIDI Player preferences (under File, Preferences, Playback, Decoding in current foobar2000 versions), then select MU map (VST). Its keyboard mnemonic is Alt+M. The choices are Do not send (use MIDI file), MU80 / Basic and MU100 / Native. Apply the setting and stop and restart playback of the song from the beginning; pausing and resuming is not sufficient. The default sends no extra map message, preserving the existing choice made by the MIDI or instrument.

This is a global VST-backend preference, including the optional VST instrument used for XG files. It is separate from Flavor: selecting a map does not force XG or GS mode. It is not saved into per-song preset tags and never rewrites MIDI files. Non-VST backends are unaffected. Instruments that do not implement Yamaha MU voice-map selection may ignore it.

The selected map is sent to all declared VST ports at instrument startup, including when a backwards seek restarts the instrument. It is reapplied immediately after recognized GM, GM2, GS and XG resets on their actual destinations, at the reset's timestamp. Explicit map messages in the MIDI are retained and can subsequently change the map until another reset reapplies the preference.

MU80 / Basic sends F0 43 10 49 00 00 12 00 F7; MU100 / Native sends F0 43 10 49 00 00 12 01 F7. These use Yamaha device number 1. Recognized voice-map messages from the MIDI are device-wide and reach every declared VST context, retaining their original device number.

Voice-map selection is not full MU80 hardware emulation and does not replace the MU instrument's samples, effects, panning or polyphony. It is not a fix for reported organ clicks. Thanks to Yamamoto for suggesting a player-side selection instead of editing MIDI files.

For a listening comparison, use a MIDI that does not explicitly select its own MU map. PhoenixA and PhoenixB are examples from the reported demos; F-Cool and R-love explicitly select Native and can override Basic. Not every patch changes between maps, so a subtle or inaudible difference alone does not prove a fault. Please report the filename, passage, instrument version and selected map when comparing with a reference.

External MIDI output

This option sends MIDI to connected instruments or virtual MIDI ports rather than rendering it through a software synthesizer. Select MIDI output (external device) in MIDI Player preferences and choose Configure. Select the Primary MIDI output (Alt+P). For two-port files, select a different Secondary MIDI output (Alt+S); otherwise you can leave it at None. Enter accepts and Escape cancels. Apply the preferences and restart the track.

Browse your normal playlist and press Enter on a MIDI file to play it. Listen through the instrument's own audio connection. Foobar's audio volume, mute, equalizer and audio effects do not control that instrument. A loopMIDI port also needs a receiving application, such as an instrument host.

Single-port files use only the primary device. In a two-port file the first and second used logical ports (normally A and B) go to the primary and secondary devices respectively. A two-port file needs both outputs; files using more than two are rejected rather than merged. Each saved output is resolved by its unique name, not its current Windows device number. If a required output is unavailable or ambiguous, the track stops with an error and no substitute is used.

Only normal playback can send MIDI. Conversion and ReplayGain scanning require a software synthesizer. External output plays a single pass plus the configured decay time; internal loop and fade settings do not apply. Foobar's playlist repeat remains available.

Bank changes, programs, controllers, pitch bends and complete SysEx messages go to the file's assigned output in file order. SysEx is sent unchanged, not rewritten or copied to the other instrument. Use files intended for your gear; two independent instruments do not necessarily interpret a file made for one shared multi-port synth the same way. A long SysEx transfer can delay later events on either output. Software-synth flavor, MU-map and MIDI-message filters are not applied.

Pause, stop and track changes silence the previous playback. Seeking and resuming restore earlier controller, program and SysEx state and restart notes still held at the selected position. This is not sample-accurate audio seeking: a restarted note begins its attack again, and a large custom-voice dump can delay restoration. The transport stops sending and silences notes if Foobar's playback-clock updates stall.

Live testing through Sound Canvas covered ordinary playback, SysEx-heavy Roland demos, pause/resume, forward and backward seeks and changing files without reported stuck notes or missing parts. The port selector uses native labelled Windows controls. Other MIDI drivers and physical instruments have not all been tested; hardware fidelity and sample-accurate timing are not promised.

Software-synth limits

Separate VST instances are not a single hardware module. They do not share its polyphony, global effect processors or cross-port receive-channel reassignment. Recognized parameters are adapted, but proprietary bulk dumps and unknown messages are not translated. Complete hardware parity is not promised.

A destination must be declared by the MIDI file. If absent, the original SysEx is preserved on its source rather than inventing a port. Declared event ports beyond the backend's capacity are not merged into another group. Existing port-number normalization is retained.

Additional instances increase resource use according to the instrument being loaded. Lazy creation avoids starting unused instances, but four expensive instruments can still require substantial CPU and memory. Single-port files should retain their existing routing.

Updates and rollback

Updates to this community fork are manual: download its newest component package, install it through Components and restart. There is no added automatic updater. The upstream component catalogue does not track this fork, and installing an upstream build may replace these changes.

The MU map preference defaults to sending nothing. External MIDI output is opt-in and has no default port; existing software-player settings continue to work. To return from external output to a software synthesizer, select that player and instrument again and restart playback. Before rolling back to a version without external MIDI output, select a software player, then install the previously retained component package and restart. Your profile backup is a separate safeguard; do not overwrite settings indiscriminately. Do not load old and new DLLs together.

Testing and feedback

Seven automated regression tests pass in each architecture, covering the parser, instrument bridge and external MIDI timeline, worker lifecycle and mock-driver buffer ownership. Coverage includes independent notes and programs, timing, SysEx, reset cycles, saved state, later port changes, unsupported or missing ports, lazy instance creation, cancellation and preserved MIDI bytes. Listening checks also covered multi-port Yamaha percussion, Roland demos and external Sound Canvas playback. Long-running workloads and all instrument combinations have not been exhaustively tested.

Please report reproducible issues with your foobar2000 version and bitness, component version, player backend, instrument version, and the MIDI filename and passage. Comparisons with the upstream component or a permitted hardware recording are useful. Share files only when you have permission; no ROMs or credentials are needed in reports.
